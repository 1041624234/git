# git — Muse × Codex 协作工地

这是彭佳的协作试点仓库，跑一套三级管理流程：彭佳定目标拍板，Muse 当经理拆解、派活、监督、验收，Codex 当员工埋头干活。

## 分工

| 角色 | 职责 |
|---|---|
| 彭佳（老板） | 定目标、拍板；合并（merge）必须经她点头 |
| Muse（经理） | 拆解目标成 issue（带验收标准）、派活给 Codex、盯进度、审 PR、做验收、向老板汇报 |
| Codex（员工） | 按 issue 写代码，提 Pull Request，按 review 意见修改，不许自作主张扩范围 |

## 流程

1. 彭佳定目标（一句话说清想做成什么）
2. Muse 拆解成小 issue，每个 issue 写明背景、范围和可检验的验收标准，彭佳点头后才派活
3. Codex 按 issue 干活，一个 issue 对一个 PR，PR 关联 issue 编号
4. Muse 审 PR：对照验收标准逐条验、看测试/CI、查范围外改动；结论为 通过 / 打回（附具体修改清单）/ 存疑（交彭佳决定）
5. 彭佳点头才合并；涉及删除数据、改生产配置、动密钥的 PR 一律停下等彭佳亲自看
6. 每个目标完结后，Muse 给一份小结：做了什么、验收结果、遗留问题

## 模板

- 新任务请用 issue 模板（自带「验收标准」一节）
- 提 PR 请按 PR 模板里的验收清单逐项勾
